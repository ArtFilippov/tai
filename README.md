Глобальная задача: создать единую систему доверенного искусственного интеллекта, в которой будут осуществляться тест устойчивости LLM моделей к различным атакам. Это подразумевает реализацию самих атак, проверку качества и устойчивости, мониторинг и контроль выдаваемой информации в диалоге, применение методов защиты и повторный замер качества.

Текущие задачи и требования:
1. Рассматриваем только Qwen семейство, в процессе разработки используем только самые лёгкие модели для запуска на CPU
2. Нужно придумать как реализовать атаки, подумать возможные модули, астракции и интерфейсы
3. Под реализацией атаки подразумевается не просто применение какого-то одного запроса, а целая стратегия, которая позволяет получить запрос для конкретной LLM 
4. В первую очередь рассматриваем атаки из garak_only_attacks.md в порядке появления
5. На первом этапе мы просто пишем свою абстракцию для атак такого типа и далее наша абстракция просто использует эту библиотеку 

Абстракции для рассмотрения, в порядке очереди на имплементацию:
1. Generator - абстракция над LLM. С ней можно делть базовые вещи как с любой LLM: давать промпт и получать ответ, прерывать генерацию
2. User или Attacker (название обсуждаемо). Имеет методы start(), stop() - неблокирующие, ничего не возвращают; и status() - не блокируюший, возвращает ClassNameStatus. Поведение и output методов обсуждаем
3. Message - методы base() -> str, to_string() -> str, dump() -> str, revert(n) -> Message, transform(function, arg_2, arg_3, ...) -> Message, spawn(payload) -> Message. Отражает любой текстовый запрос или ответ, иммутабельный. Хранит в себе цепочки превращений, например внутри Generator может быть цепочка начинающегося с системного промпта (то что возвращает base()), и на каждом шаге идёт трансформация под действием запроса пользователя.
4. Сначала реализуем атаку fitd.FITD
