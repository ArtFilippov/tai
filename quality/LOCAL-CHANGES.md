# Локальная интеграция Python Quality 1.0.0

Поставка установлена в tai 2026-09-21. Реальные smoke-тесты установщика прошли;
версии инструментов сохранены в `tools.json`. В полном прогоне на проекте выявлены
и исправлены две ошибки исполнения:

1. `check.py`: каталог `raw/` создаётся при подготовке задач, до старта анализаторов.
   Pylint открывает файл `--output` сразу; раньше создание каталога зависело от того,
   успел ли другой анализатор завершиться и сохранить stdout/stderr.
2. `_pylint_worker.py`: локальная совместимость с Pylint 4.0.8 для алиасов методов
   pathlib, например `write_text = Path.write_text; write_text(...)`. Нативный
   `_check_open_call` обращается к `attrname` у AST-узла `Name`, где этого поля нет.
   Обёртка временно предоставляет уже определённое имя функции и вызывает исходную
   проверку; после вызова AST восстанавливается. Правила `bad-open-mode` и
   `unspecified-encoding` продолжают выдавать диагностику.

Регрессии проверяются настоящим Pylint в изолированных временных проектах:

```bash
uv run --locked --group dev python -m unittest discover -s quality/tests
```

Тесты проверяют первый запуск с новым каталогом отчёта, сохранение native JSON,
диагностику неизвестного имени, неверного режима открытия и отсутствующей кодировки,
а также отсутствие ошибки на вызове с явно заданной кодировкой.

Для обычной установки клона используйте `uv sync --locked --group dev`. При обновлении
или повторной установке из `.run` перенесите эти локальные исправления: установщик
заменяет управляемые `quality/check.py` и `quality/_pylint_worker.py`. После обновления
Pylint пересмотрите необходимость обёртки и выполните регрессионные тесты и полный check.

При интеграции `tach.toml` получил слои и публичные интерфейсы для исходных
26 файловых границ. После перегруппировки в `app`, `attacks/fitd`, `alert` и `core`
карта содержит также границы новых пакетов и выделенных модулей оценивания/состояния.
Контрактные `__init__.py` имеют явные списки экспортов; файловые проверки слоёв
сохранены внутри компонентов. Назначение структуры описано в корневом `README.md`.
`architecture.ready.json` подтверждает принятие конфигурации, а не отсутствие
нарушений в исходниках.

Для новой иерархии особенно заметны ограничения архитектурных эвристик плагина
1.2.2. `W9004` распознаёт внутренние импорты по фиксированным частям имени
(`domain`, `dto`, `use_cases`, `protocols`, `models`), поэтому сообщает о forbidden
I/O также на чистых импортах из `core` и контрактных `__init__.py`. `W9201` ищет
Protocol в пути с буквальным `.domain.`: настроенное назначение слоя Domain не
учитывается этой проверкой. Поэтому явный контракт `ObservedChat(EvaluationChat)`
всё ещё получает это сообщение. Эти диагностики остаются в полном отчёте;
правила, слои и исключения для их подавления не изменялись.
