# Внешнее сохранение итога запуска (#21)

`FITDUser` выполняет стратегию без параметров каталогов и без файлового хранения.
`wait()` ждёт рабочий поток, включая освобождение участников; он не сохраняет
результат. Наблюдение во время атаки обеспечивает [независимый журнал](run-journal.md).
CLI и серия используют общий внешний модуль `core.runs.storage`.

Те же правила действуют для `AdaptiveAttacksUser` и `AdaptiveAttacksExperiment`:
общий снимок и writer сохраняют фактический финальный Message и только его оценку.

```python
from tai import FITDExperiment, capture_run, save_run

experiment = FITDExperiment(target, attacker, base, evaluator, journal_dir="runs")
experiment.start()
journal = experiment.journal
experiment.wait()
record = capture_run(experiment, journal=journal)
directory = save_run(record, "runs")
```

## Снимок и файлы

- `User.snapshot()` атомарно возвращает неизменяемый `RunSnapshot(status, result)`
  завершённого выполнения. До запуска и до выхода рабочего потока он отклоняется,
  даже если уже виден терминальный статус. `status` содержит причину, счётчики и
  связанную оценку; `result` — исходный неизменяемый Message либо `None`.
- `capture_run` создаёт `RunRecord`: этот снимок и отделённую диагностическую копию
  метаданных. Результат и окончательный статус берутся только из User. Журнал даёт
  доступные начальные/итоговые настройки и общую политику редактирования; журнал
  другого запуска отвергается. Настройки снимаются сборкой эксперимента, итоговые —
  до освобождения участников. Отсутствующий снимок настроек представлен `null`.
- Для User без журнала можно передать `settings=…`, `final_settings=…`,
  `redactor=…` из собственной сборки. Без `journal_dir` FITDExperiment ведёт журнал
  в памяти. Ни захват, ни сохранение не вызывают участников и не читают приватные
  поля User.
- `save_run(record, artifacts_dir)` возвращает каталог `<artifacts_dir>/<run_id>`.
  `result.txt` записывается из `record.snapshot.result.to_string()` без редактирования,
  усечения и восстановления из событий. Пустой Message даёт пустой файл;
  при `None` файла нет. Последний фактически предъявленный результат сохраняется
  также при остановке/ошибке; отброшенный или ещё не принятый ответ его не заменяет.
- `metadata.json` содержит `state`, `run_id`, `progress`, `reason`, `result_id`,
  `evaluation`, диагностический `result` с происхождением, `settings`, `final_settings`.
  `evaluation=null` отличается от `{result_id, success: false}`. Оценка обязана быть
  строгой boolean и принадлежать именно итоговому Message.

Итоговые файлы создаются только внешним writer после завершения рабочего выполнения.
Каждый файл заменяется атомарно; пара файлов не является общей транзакцией.
`record.metadata` возвращает новую JSON-копию при каждом чтении. Сохранённый record
остаётся согласованным после повторного `start()` и может быть записан позднее
в другой каталог. Его метаданные не содержат пути назначения.

## Ошибки и остановка

Исключения `capture_run` / `save_run` явно передаются вызывающему коду. Отказ записи
не меняет состояние завершившегося User и не отравляет его журнал; частично
записанные файлы нельзя считать успешным сохранением. При желании вызывающий код
может повторно сохранить тот же record.

CLI обрабатывает Ctrl+C флагом, ждёт User и сохраняет итог также при остановке и
ошибке выполнения. Повторные сигналы сохраняют ожидание и запись. Сигнал во время
сохранения даёт код 130, но уже завершённый `COMPLETED` остаётся `COMPLETED`.
Ошибка внешнего сохранения явно печатается и даёт ненулевой код команды.

Серия сохраняет каждую попытку до освобождения её места в лимите `jobs` и фиксирует
`storage_error` отдельно от фактического исхода. Другие активные User могут
продолжать работу; все исходы публикует один координатор по sequence. Ошибки общих
файлов завершают команду после остановки и ожидания активного набора. Относительные
ссылки индекса сохраняют смысл при перемещении всего каталога серии; независимый
пересчёт читает только индекс. Подробности: [alert-series.md](alert-series.md).

Офлайн-проверки: `tests/test_storage.py`, сквозные FITD/CLI-тесты и тесты серии.
Архивные материалы живой приёмки от 2026-09-15 сохраняют прежнюю схему с ревизиями
файловой финализации; новые метаданные не содержат `finalization_revision`.
