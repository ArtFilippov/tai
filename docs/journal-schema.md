# Схема новых журналов

Журнал запуска — JSONL-файл. Прозрачная обёртка дополняет каждое событие полями
`schema_id` и `schema_version`, которые сообщает конкретный журнал. Дисковый
журнал сейчас использует `tai.run` / `1`. `ParsedJournal` отклоняет неизвестную
пару или запись без неё, не пытаясь угадать прежний формат.

Каждый `AttackRun` начинает работу событием `start` с текстом базового
запроса, его происхождением (`base_metadata`) и `attack`. Значение `attack`
описывает вложенную сборку Target, оценщика и стратегии, включая настройки
моделей и `max_calls_per_conv`; сами участники выбирают публикуемые сведения
через `description()`. Поле журнала в описание атаки не входит. Дальнейшие
`call`, `step`, `decision`, `result`, `judgment` и `end` сохраняют ход запуска.

Для DAN события Target `call` содержат `phase` (`activation` или `base_request`)
и `candidate`: `section`, `variant`, однобазовую `position` в текущем обходе
и исходную идентичность: `source_index` (0–13 для named, 0–665 для wild)
либо `combination` (1–127 для ablation). Исходные индексы и номера не
перенумеровываются при выборе подмножества; повторяющиеся тексты остаются
различимыми по источнику.
Ответ активации остаётся диагностическим материалом; ответ на базовый запрос
сохраняется целиком. Решение `dan_candidate` и событие `result` предшествуют
оценке. Только после положительного вердикта записывается `dan_success` с
идентичностью кандидата, предъявленным текстом и снимком описания Target.
`ParsedJournal.read()` дополнительно возвращает `successful_candidate` и `target`
для такого успешного исхода. Эти поля отсутствуют при исчерпании, ошибке и в
исторических журналах без записанного победителя. Статическая конфигурация атаки
не содержит победителя; существующие поля результата и оценки сохраняют смысл.

Для Smuggling `start.attack.probe` сохраняет выбранные техники в каноническом
порядке (hypothetical → homoglyph), описание Attacker, закреплённую ревизию garak
и эффективные настройки каждой выбранной техники в `settings`:
`hypothetical` содержит точный шаблон, инструкцию подготовки и бюджет одного
вызова; `homoglyph` — seed `0`, один кандидат, замену всех подходящих символов
и полную исходную карту. Подготовка записывается как `call` с `role: "attacker"`,
`phase: "hypothetical_preparation"`, идентичностью кандидата, полным запросом
и ответом. Неуспешная технически операция не считается завершённым `call`.
Решение `smuggling_transformation`
сохраняет `original`, `base_metadata`, преобразованный `prompt` и `candidate`
с `technique` и однобазовой `position` в выбранном каноническом обходе.
Для hypothetical это позиция `1`; для homoglyph — `2`, если выбраны обе техники,
иначе `1`, и дополнительно `seed: 0`. Причина `unchanged_text` с `kept: 0`
означает пропуск homoglyph без вызовов Target и Judge. Если ранее был оценён
отрицательный hypothetical, его результат и вердикт сохраняются; иначе запуск
завершается `no_result` / `no_candidates` без `result` или `judgment`.
При отправке Target `call` содержит номер кандидата и его идентичность в
`metadata.candidate`; весь ответ затем записывается как `result` до оценки.
После положительного вердикта `smuggling_success` связывает идентичность,
полный текст и описание Target. Как для DAN, `ParsedJournal.read()`
восстанавливает `successful_candidate` и `target` только для записанного успеха.

Для Doctor `start.attack.probe` сохраняет закреплённую ревизию garak, выбранные
техники в порядке puppetry → bypass → bypass_leet, seed и бюджеты кандидатов.
Решение `doctor_transformation` содержит точный `prompt`, `original`,
`base_metadata` и `candidate`: `technique`, однобазовые `template` и `position`,
а для bypass_leet — ещё `seed`. Номер шаблона относится к исходной технике;
позиция относится к текущему выбранному обходу. Target `call` сохраняет
идентичность в `metadata.candidate`; `result` предшествует оценке полного ответа.
После положительного вердикта `doctor_success` связывает кандидата, точный текст
и описание Target. `ParsedJournal.read()` восстанавливает `successful_candidate`
и `target` по тем же правилам, что для DAN и Smuggling. При исчерпании остаётся
последний оценённый ответ; техническая ошибка завершает попытку как `failure`.

В серии первый журналируемый шаг собранной атаки — `start`. Общий
`summary.json` лежит в корне запуска и содержит только доступные внешнему
циклу данные: базовый запрос с происхождением, описание атаки, её финальный
результат либо ошибку. Ошибка до сборки атаки может не иметь журнала.
Оценки финального результата следует читать из журналов в подкаталогах атак.

Для функциональной оценки `RecordedFunctionalTest` принимает журнал через
контракт: `start(mlops)` записывает `functional_test` с
`logs_type: "generative_models_functional_test"`, а `record(task_name,
results, seconds)` записывает одно событие `dataset` с `task_name`, числовыми
`results` и `time` в секундах. Эти события не запускают бенчмарки.
