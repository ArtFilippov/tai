# Общий ленивый vLLM и ограниченная параллельность ALERT

Принято в рамках [#23](https://github.com/ArtFilippov/tai/issues/23), срезы #24–#27.

Серия допускает записи в порядке манифеста при положительном лимите `jobs`
(по умолчанию 4). Каждая запись получает независимые чаты трёх ролей, модельный
оценщик и журнал. Один координатор публикует активные записи и обновляет их
окончательные исходы по постоянному `sequence`; завершение может быть не по порядку.
Место занято до завершения worker, освобождения участников и внешнего сохранения.

Сборка создаёт один `QwenServer`. Первый запрос запускает одну управляемую сессию
vLLM; одновременно пришедшие запросы ожидают общий результат старта. После готовности
HTTP-запросы не держат блокировку инициализации; continuous batching выполняет vLLM.
История и контрольные точки остаются в `LLMChat`, согласно [ADR 0002](0002-dialogue-owned-by-llm-chat.md).
Чтение состояния сервера и настроек чатов не запускает процесс и не импортирует GPU-библиотеки.

Это дополнительный backend к [ADR 0003](0003-local-qwen-for-live-acceptance.md):
существующий Transformers-исполнитель продолжает сериализовать генерации, а
vLLM использует отдельное закреплённое окружение и процесс. Подготовка зависимостей
и snapshot отделена от исполнения. Выбранный профиль и проверенная совместимость
описаны в [docs/vllm.md](../vllm.md).

Общий Rich-дисплей относится к Interface; `ConsoleRow` — Domain-порт.
Infrastructure-декоратор `ConsoleRunJournal` сохраняет файловый RunJournal и
напрямую обновляет строку из `bind`, `call`, `observe`, `finish`. Стек методов
локален журналу. Bootstrap передаёт фабрику журнала в FITDExperiment до создания
рабочих объектов. UI не восстанавливается из потока сохранённых событий;
обновления координатора явно обозначают остановку и внешнее сохранение.

SIGINT только выставляет флаг. Координатор останавливает все активные User,
сохраняет завершившиеся допущенные обращения/оценивания и ждёт worker cleanup.
Общий сервер закрывается после пользователей: SIGTERM группе, ограниченное
ожидание, затем SIGKILL оставшимся workers. Отмена отдельного HTTP-обращения не
отменяет другие роли и отличается от остановки User между вызовами.
