# Локальный Qwen для живой приёмки

Принято 2026-09-15; реализовано в рамках [#12](https://github.com/ArtFilippov/tai/issues/12).

Живая приёмка FITD использует Qwen2.5-0.5B-Instruct внутри tai через Transformers
на одной CUDA GPU с FP16. Зависимости и закреплённые веса подготавливаются отдельным
шагом; эксперимент выполняется из локального кеша без сети. Выбор пересматривает
отсрочку локального Qwen в #1 и требование HTTP-прогона в #9 после блокеров доступа
к Zen. Цена решения — опциональные зависимости Transformers/PyTorch, подготовка
весов и собственный жизненный цикл локального инференса вместо зависимости от
доступности внешнего API.

Target и Attacker используют одну загруженную модель при независимых LLMChat:
общими являются веса, а истории, контрольные точки, идентификаторы разговоров и
сигналы отмены принадлежат своим собеседникам. Это сохраняет
[владение историей в LLMChat](0002-dialogue-owned-by-llm-chat.md) и
[единый текстовый результат](0001-textual-attack-contract.md). Отмена локального
инференса обрабатывается между шагами декодирования; мгновенное прерывание
выполняющегося CUDA kernel или загрузки модели не обещается.

На Qwen переносится живая приёмка; управляемые офлайн-тесты дополняются контрактными
проверками нового адаптера. Приёмка требует многоходового настоящего FITD,
штатного завершения с Message и сохранённых артефактов, а успешность атаки
фиксируется отдельно. Условия и фактические результаты проверяются в
[#9](https://github.com/ArtFilippov/tai/issues/9).

Реализация загружает закреплённый snapshot из явно выбранного Hub-кеша только
при первом send. Общий исполнитель сериализует генерации и не хранит KV-cache
между вызовами; отмена ожидания не отменяет другую роль. Диагностические снимки
не импортируют опциональные библиотеки и не запускают загрузку. Итоговые настройки
дополняют начальный снимок наблюдённым dtype после реального исполнения.

[Отчёт 2026-09-15](../acceptance/2026-09-15-qwen.md) подтверждает CUDA/FP16 preflight
обеих ролей и многоходовой FITD с COMPLETED и отрицательной оценкой результата.
Внешняя сеть была отключена через network namespace; полный журнал и Message
сохранены для итоговой приёмки #9.

[Итоговая приёмка #9](../acceptance/2026-09-15-fitd.md) повторила preflight и FITD
из чистого экспорта закреплённой ревизии tai: 24 реальных обращения, COMPLETED,
Message и связанная отрицательная оценка. Чистая установка Python 3.12/uv,
офлайн-проверки и полные опубликованные материалы закрывают приёмочные критерии.
